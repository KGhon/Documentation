[Title]
Twine Analyzer

[Overview]
The Twine Analyzer is a Twine HTML parser that lets you visualize, select, and export passages to other formats. It requires that your Twine stories follow specific markup for the parsing to work.

[Dependencies]
<li>Godot 4.4.3</li>

[Navigation]
The Twine Analyzer exists as a main screen plugin you can swap to at the top of Godot's editor window. Twine analyses can be opened in 3 ways in a Godot project:<ul>
<li>Create a new KDTTwineAnalysis resource. Double-clicking any resource will open a Twine analysis that also saves the Twine HTMLs you import into that resource.</li>
<li>Right-click a Twine HTML file and select at the bottom of the context menu "View In Twine Analyzer". This will create a temporary Twine analysis that does not save any data.</li>
<li>The TwineAnalysisWidget can be embedded inside of a Board which can link to either a KDTTwineAnalysis resource or Twine HTML file. Opening a resource will save data, opening a Twine HTML will be temporary and not save anything.</li></ul>

[AdditionalContextMenuItems]
The Twine Analyzer plugin provides a few quality of life features to make coordinating between Godot and Twine easier. Twine must be installed for this to work.<ul>
<li>You can open a Twine HTML file in Twine from Godot by right-clicking the HTML file and selecting "Open In Twine" at the bottom of the context menu. This will automatically open Twine with the library folder set the location of the HTML file, allowing it to be selected without having to manually set the library folder every time Twine is opened.</li>
<li>If you want to create a new Twine HTML in a specific folder, you can right-click the folder and select "Open Twine Here". This will open Twine with the library folder set to the location so any new stories will be automatically created in your chosen folder.</li></ul>

[Features]
<ul><li>View multiple Twine stories at the same time. Use the "Show" and "Scope" buttons to set what stories are visible and considered when searching for text. Hold Ctrl to multiselect.</li>
<li>Use the search box to find passages that contain certain text. By default, all story passage names and passage texts are considered. To limit seach scope:<ul>
<li>Set the story scope using the 'Scope' button.</li>
<li>Begin your query with 'n' followed by a space to only search passage names.</li>
<li>Begin your query with 't' followed by a space to only search passage text.</li></ul></li>
<li>You can selectively view passages via the Script panel by selecting any number of passage nodes in the graph view. The passages will be populated in tree order so they can be read linearly. You can select a node and all of it's parents by Shift-clicking a node.</li>
<li>The Info panel provides summarized information about imported stories. This panel is also used to remove stories from the analyzer.</li>
<li>The built-in exporter panel allows you to export your selected passage nodes into various formats.</li>
<li>Adjacent to the Twine Analyzer tab is a shortcut to open the Batch Exporter.</li>
<li>Automatic refresh when returning to the Godot editor or refocusing the Twine Analyzer panel.</li></ul>

[Export]
<ul><li>CsvLines - Export all lines from selected passages for the selected characters CSV files.The data is formatted as Line,Speaker,Receiver,Direction. A line is considered any text that is not enclosed in Syntax.</li>
<li>Script - Exports the selected passages as a text file with script formatting, removing all parsing syntax and adjusting text like a screenplay (all text is still left aligned unlike the Script view in the Twine Analyzer).</li></ul>

[TwineMarkup]
This syntax is used to parse the file for data as well as formatting when analyzing passages from a Twine story so they can be viewed like a traditional screenplay format.

[VariableSheet]
The starting node must be a node called 'VariableSheet'. Use this node to define variables for things like characters and their names. Adding a prefix to your variable can also provide additional sorting when doing analysis.

[VariableSheetExample]
&lt;&lt;set $char_mc="themaincharacter"&gt;&gt;

[Speaker]
A speaker is enclosed between two sets of 3 dashes.

[SpeakerExample]
---$char_speaker---

[Receiver]
A receiver directly follows the speaker inside the dashes and separated by 3 underscores.

[ReceiverExample]
---$char_speaker___$char_receiver---

[Descriptions]
Descriptions are enclosed between two sets of 3 equal signs. They are matched by pairs, being on the same line or space inbetween does not matter.

[DescriptionExample]
===
Description here.

More description here. The space above doesn't matter.
===

[Directions]
Directions are enclosed between two sets of 3 asterisks. They are matched by pairs, being on the same line or space inbetween does not matter.

[DirectionExample]
***
Directions about context, tone, mood, feelings, etc. like screenplay formats.
***

[Locations]
Locations are enclosed between two sets of 3 pound signs.

[LocationExample]
###Location name###

[TwineBatchExporter]
The Twine Batch Exporter is an independent program that can be run to batch process and export data from any number of Twine HTML files. Twine does not need to be installed to work. To run the exporter, locate the executable at

<i>projectname/addons/KDocumentationTools/TwineBatchExporter/TwineBatchExporter.exe</i>

Current supported export types:<ul>
<li>CsvLines - Export all lines for selected characters as CSV files. The data is formatted as Line,Speaker,Receiver,Direction. A line is considered any text that is not enclosed in markup.</li></ul>
