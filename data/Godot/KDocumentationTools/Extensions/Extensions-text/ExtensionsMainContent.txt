[Title]
Extensions

[Category]
KDocumentationTools

[Overview]
Extensions are a set of classes meant to be used to create additional documentation tools and assets within Godot that can be used in the editor alongside Boards.

[Dependencies]
<li>Godot 4.6.3 with C# support</li>

[Guide]
Extensions are Resources. Use extensions by opening the create Resource window and selecting an extension class (inherits from KDTExtensionResourceBase). You can create multiple files based on the extension that each hold separate, unique data. To view and modify the data in the extension, simply double click the Resource file to open it in a new tab in the KDT Extension Editor. Extensions can also be viewed on Boards using the Extension Reference widget. It's recommended that extensions be read only when viewed in Boards.

Extension windows are split up into two sections. On the left is the extension UI and on the right a section for editing inspectable UI elements, toggling between viewing as an embedded tab or window, and a notes area. Based on how the extension is set up, selecting UI elements can populate the inspectable area to allow nesting data inside the UI element.

[ExtensionResource]
Your extension Resource should inherit from KDTExtensionResourceBase. You must override and define the PackedScene variable named 'extensionTemplate' with the scene that contains all the functionality of the extension. Add any data as 'Export' public variables that your extension will need to save that is not tied to a UI element (ie. data that is stored on the extension class and not the UI node classes).

[ExtensionClass]
Your extension class should inherit from KDTExtensionBase and handle the basic functionality of your extension scene. The extension class can implement the OnInitialize() virtual function to handle setup. The OnSave() and OnLoad() virtual functions are provided if you need to save data directly to the extensions Resource. Cast the 'resource' variable to your extension Resource to set and get data. Since you will probably be allowing UI nodes handle themselves, save and load will need to be handled on their individual node classes (see Saving Data below).

[ExtensionScene]
Then extension scene can be built like any UI normal UI node tree. The only requirements are that the root node should have your extension script attached and any custom classes need to be marked with the 'Tool' attribute. This scene is the scene you assign to the 'extensionTemplate' variable in the extension Resource.

[SavingData]
If your extension scene includes custom UI node classes or instantiates nodes at runtime, you'll need to manually implement saving and loading using the ISaveable interface on each custom class. When saving, extensions automatically gather data to store by iterating though all nodes in the scene tree that implement the interface. You must implement the Save(), Load(), and GetSaveDataClass(). The GetSaveDataClass() function returns the type of class to use for saving your cusotm UI data. In the Save() and Load() functions cast the save data parameter to the save data class you use in the GetSaveDataClass() function. Once cast, you can then set or get saved data.
